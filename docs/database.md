# データベース設計書（Peewee / SQLite）

本アプリで使用するデータベースの構造と、テーブル間のリレーション（関係性）の定義です。データベースファイルはプロジェクト直下に `app.db` として保存します。

---

## 1. データベース概要
*   **DBMS**: SQLite
*   **ORM**: Peewee
*   **DBファイル名**: `app.db`（プロジェクト直下）

---

## 2. テーブル一覧と役割

初学者が迷わないよう、なぜそのテーブルが必要なのかの理由と役割を整理しています。

| テーブル名 | クラス名 (Peewee) | 役割・なぜ必要か |
| :--- | :--- | :--- |
| **ユーザーテーブル** | `User` | アプリを使う人の情報を管理します。誰がログインしているか、誰が投稿したかを識別するために必要です。 |
| **投稿テーブル** | `Post` | ユーザーがシェアした写真やキャプションなどの投稿データを保存します。タイムラインで一覧表示するために必要です。 |
| **いいねテーブル** | `Like` | 「誰が・どの投稿にいいねしたか」の履歴を保存する中間テーブルです。1人が同じ投稿に何度もいいねできない（重複防止）ようにするために必要です。 |

---

## 3. 各テーブルの詳細設計

### ① User（ユーザー）テーブル
ユーザー情報を管理するテーブルです。`Flask-Login` の仕組みと連携できるように設計しています。

*   **主キー**: `id`
*   **ユニーク制約**: `username`, `email`

| カラム名 | データ型 (Peewee) | 制約・オプション | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | `PrimaryKeyField` | PK, 自動採番 | ユーザーを一意に識別するID |
| `username` | `CharField` | Unique, Not Null | 画面に表示するユーザー名 |
| `email` | `CharField` | Unique, Not Null | ログインなどに使用するメールアドレス |
| `password` | `CharField` | Not Null | ハッシュ化されたパスワード文字列 |

---

### ② Post（投稿）テーブル
ユーザーが投稿した写真とキャプションを管理するテーブルです。どのユーザーが投稿したかを紐付けるため、外部キーを持ちます。

*   **主キー**: `id`
*   **外部キー**: `user_id` （`User` テーブルの `id` を参照）
*   **インデックス候補**: `user_id`, `created_at` （ユーザーごとの投稿検索や、新着順での並び替えを高速化するため）

| カラム名 | データ型 (Peewee) | 制約・オプション | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | `PrimaryKeyField` | PK, 自動採番 | 投稿を一意に識別するID |
| `user` | `ForeignKeyField` | FK (`User`), 外部キー制約 | 投稿したユーザー（UserモデルとN:1の関係） |
| `image_filename` | `CharField` | Not Null | 保存された画像ファイル名（例: `abc123.jpg`） |
| `caption` | `TextField` | Nullable（任意） | 写真に添える短いキャプション |
| `created_at` | `DateTimeField` | `default=datetime.now` | 投稿日時（自動記録） |

---

### ③ Like（いいね）テーブル
「どのユーザーがどの投稿にいいねしたか」を記録する中間テーブルです。

*   **主キー**: `id`
*   **外部キー**: `user_id` (`User`), `post_id` (`Post`)
*   **ユニーク制約**: `user` と `post` の組み合わせに対してユニーク制約（複合ユニーク）を付与し、同じユーザーが同じ投稿に重複していいねできないようにします。
*   **インデックス候補**: `user_id`, `post_id` （いいねの集計や、ユーザーがどの投稿にいいねしたかの検索を効率化するため）

| カラム名 | データ型 (Peewee) | 制約・オプション | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | `PrimaryKeyField` | PK, 自動採番 | レコードを一意に識別するID |
| `user` | `ForeignKeyField` | FK (`User`), 外部キー制約 | いいねを押したユーザー |
| `post` | `ForeignKeyField` | FK (`Post`), 外部キー制約 | いいねされた投稿 |

---

## 4. Peeweeで実装する場合の注意点

1. **外部キーのフィールド名と指定**
   * Peeweeでは `ForeignKeyField(User, backref='posts')` のように定義します。これにより、Pythonコード側で `user.posts` と書くだけで、そのユーザーが投稿したすべてのリストを簡単に取得できるようになります。
2. **複合ユニーク制約（重複防止）の書き方**
   * `Like` テーブルで「1人1回まで」を実現するためには、モデルの `Meta` クラス内で `indexes = (((user, post), True),)` のように設定し、ユーザーと投稿のペアが重複しないようデータベースレベルで制限をかけます。
3. **データベース接続の管理**
   * FlaskでPeeweeを使う際は、リクエストが始まったタイミングでデータベースに接続（`connect()`）し、リクエストが終わったら切断（`close()`）するミドルウェア（またはフック）を忘れないように設定する必要があります。
